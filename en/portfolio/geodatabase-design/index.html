A municipal parcels and utilities data model in GeoPackage, with a data dictionary and integrity rules

We designed 8 feature classes, 15 domains (10 coded lists) and 4 relationships, built them in a GeoPackage with triggers that reject out-of-domain values and missing references, and loaded an OpenStreetMap sample of a Riyadh neighbourhood.

A demo built from open data, not a client project.

The problem

Scattered layers with different names and fields, no domains and no rules, so the same errors come back with every edit and handover.

The data

OpenStreetMap sample through the Overpass API on 2026-11-20: roads, buildings, power lines, street lights, fire hydrants and the district boundary in the box 24.732 to 24.748 N, 46.572 to 46.588 E. Licence ODbL, © OpenStreetMap contributors.

The method

  1. Define the whole model in one table in the code: classes, fields, types, domains and relationships; everything is built from it.
  2. Build a GeoPackage in UTM 38N and register the domains with the GeoPackage schema extension (gpkg_data_columns and gpkg_data_column_constraints) so QGIS and GDAL can read them.
  3. Integrity rules as SQLite triggers: unique non-null keys, required fields, values inside the domain, and references that exist across tables.
  4. Load the sample: roads as mapped, blocks derived from the road network, buildings linked to the block holding their centre, lights to the nearest road.
  5. Check the spatial rules and report what fails instead of deleting it.

The result

Loaded: block 141, parcel 0, building 568, road 259, water_main 0, power_line 0, street_light 66, fire_hydrant 7. The rules rejected 7 of 7 deliberately wrong edits and accepted a valid parcel. Spatial checks: 0 building overlaps over 1 m², 2 buildings outside blocks, 21 unconnected road ends inside the box, 0 lights with no road within 40 m.

Limits

Demonstration on open data, not a client project. OpenStreetMap holds no cadastral parcels or water mains here, so the parcel and water_main classes are empty and are filled from client data; blocks are derived from roads and are not legal boundaries. The quality of loaded data follows OpenStreetMap. The design is for a GeoPackage and does not cover server databases, user permissions or the Utility Network model. WGS 84 / UTM 38N is used for the demo; a real project uses the authority's system, such as KSA-GRF17.
