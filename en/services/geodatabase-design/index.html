Spatial Database and Data Model Design

Designing a spatial database: feature classes, attributes, domains, relationships and integrity rules, with a written data dictionary.

Quoted per scope

Delivered by Madar

Request this service

The problem

Scattered layers with different names and attributes, no domains and no rules, so the same errors return with every edit and handover.

Who it is for

Contractors and offices preparing as-built handovers, small organisations starting their database, and GIS teams sorting out accumulated data.

What you receive

  • An empty File Geodatabase or GeoPackage in the agreed schema.
  • A data dictionary in PDF and Excel: every class, attribute and domain.
  • Documented integrity and topology rules.
  • Existing data loaded into the schema, if requested.

What you supply

  • The current data or a sample.
  • The owner's specification or data model, if any.
  • Who will use the database and for what.

How the work goes

  1. We review the current data and the owner's specification.
  2. We propose the schema in a table for your approval.
  3. We build the database, domains and rules and test them on a sample.
  4. We deliver the database and dictionary with a walkthrough call. The acceptance period is 7 days.

Accuracy and limits statement

Design for a file geodatabase or GeoPackage. It does not cover server-based enterprise databases or user permissions. The quality of loaded data follows the quality of its source.

Out of scope

  • ArcGIS Enterprise or server database administration
  • Data entry from scratch
  • Utility Network model

Tools

  • ArcGIS Pro
